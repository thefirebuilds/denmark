# Automatic toll attribution

Toll sync matches `toll_charges.trxn_at` (when the toll occurred), not `posted_at` or the import time, to the same vehicle's non-deleted, non-canceled reservation. Assignment begins only after the car was made **Ready for handoff**, and never before the reservation's `trip_start`. It stops at the recorded `returned_at` when a nonblank `return_detected_location` is present. That return boundary is exclusive: tolls at or after arrival belong outside the guest's window. A known early return shortens the window; a known late return extends it beyond the scheduled end. Without a recorded location return, `trip_end` remains the conservative upper bound (inclusive). There is no arbitrary pre-trip or post-trip grace period.

Readiness is checked at the toll's occurrence time using `trip_stage_history`, including later revocations back to Booked/Confirmed/Canceled and subsequent re-entry into Ready for handoff. The trip's current stage at import time is not used as a blanket gate: an old in-window toll can still match after return or completion. A currently Ready for handoff trip with no history can use its non-null `stage_updated_at` as evidence; that fallback never overrides recorded history. Older trips without proof of a handoff-ready time stay unassigned for manual review. If more than one trip is eligible, the toll stays unassigned rather than choosing one arbitrarily. No new timestamps or schema migrations are needed; existing stage history and return-location records are reused.

For example, an October 27 reservation starting at 8 PM America/Chicago cannot receive a toll incurred at 6:57 PM that evening. A transfer drive between reservations remains vehicle-matched and trip-unassigned unless an owner explicitly assigns it. Normal manual assignment remains available for reviewed exceptions.

On each successful toll sync, before backfilling unassigned tolls, the service rechecks the same handoff/start/return policy and detaches ineligible matches only when provenance is `automatic_sync`, charge review status is blank/pending/matched, the trip is neither billed nor waived, there is no charged total, and the charge is absent from billing snapshots. This includes an automatic assignment with no recorded readiness evidence. It preserves the matched vehicle. The existing assignment-history trigger records the detach under the sync actor, and the existing cache refresh recalculates affected trip totals, including trips left with no tolls. Ignored/dismissed tolls are not automatically reassigned.

Manual, already reviewed, billed, waived, legacy/unknown-provenance and billing-snapshot records are not rewritten automatically. Review those explicitly if an old charge was assigned incorrectly. Sync-run metadata and the returned summary report `recordsClearedOutsideTrip`; committed corrections log `[tolls] cleared automatic out-of-window assignments` with a count. Deploy the updated backend, then run the normal toll sync (or wait for its scheduled run). No schema migration or new settings are required. This code change does not itself correct a production charge until that sync runs.
